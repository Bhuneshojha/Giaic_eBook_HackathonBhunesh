# Chapter 6: Gazebo and Unity - Digital Twin Environments

Digital twin technology plays a crucial role in robotics development, allowing for safe, cost-effective testing and validation of complex robotic systems before deployment in the real world. This chapter explores two leading simulation environments—Gazebo and Unity—each offering unique advantages for different aspects of humanoid robotics development. We'll examine their capabilities, integration with ROS 2, and best practices for creating realistic simulation environments.

## 6.1 Introduction to Digital Twin Technology

### 6.1.1 Definition and Concept

A digital twin in robotics is a virtual replica of a physical robotic system that mirrors its behavior, properties, and interactions with the environment in real-time. This virtual representation allows for:

- **Testing and Validation**: Experiment with algorithms and behaviors without risk to physical hardware
- **Training and Development**: Provide safe environments for testing complex behaviors
- **Performance Optimization**: Analyze system behavior under various conditions
- **Hardware-in-the-Loop Integration**: Test real algorithms with simulated sensors and actuators

### 6.1.2 Benefits of Simulation in Robotics

1. **Safety**: Test dangerous scenarios without risk to equipment or humans
2. **Cost Reduction**: Minimize wear on physical hardware and reduce operational costs
3. **Repeatability**: Execute identical experiments multiple times for consistent results
4. **Speed**: Accelerate development cycles by running multiple scenarios in parallel
5. **Accessibility**: Enable development without access to physical hardware

### 6.1.3 Simulation Fidelity Trade-offs

The simulation fidelity affects both realism and computational requirements:

- **High Fidelity**: Accurate physics, detailed graphics, realistic sensor models
- **Medium Fidelity**: Balance between accuracy and performance
- **Low Fidelity**: Fast execution, simplified physics for algorithm development

## 6.2 Gazebo Simulation Environment

### 6.2.1 Architecture and Components

Gazebo is a physics-based simulation environment that provides realistic sensor simulation and robust physics modeling. Key components include:

- **Physics Engine**: Open Dynamics Engine (ODE), Bullet, or Simbody for accurate physics simulation
- **Sensor Simulation**: Cameras, LIDAR, IMU, GPS, and other sensors with realistic noise models
- **Rendering Engine**: OGRE for 3D visualization and graphics
- **Plugin System**: Extensible architecture for custom sensors and controllers

### 6.2.4 Gazebo ROS 2 Integration

Gazebo integrates seamlessly with ROS 2 through the Gazebo ROS packages:

// Example of launching Gazebo with ROS 2
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"
#include "geometry_msgs/msg/twist.hpp"

class GazeboIntegration : public rclcpp::Node
{
public:
    GazeboIntegration() : Node("gazebo_integration")
    {
        // Subscribe to velocity commands for simulated robot
        cmd_vel_sub_ = this->create_subscription<geometry_msgs::msg::Twist>(
            "/cmd_vel", 10,
            std::bind(&GazeboIntegration::cmd_vel_callback, this, std::placeholders::_1));

        // Publish sensor data from simulated robot
        laser_pub_ = this->create_publisher<sensor_msgs::msg::LaserScan>(
            "/scan", 10);
    }

private:
    void cmd_vel_callback(const geometry_msgs::msg::Twist::SharedPtr msg)
    {
        // This command will be sent to the simulated robot in Gazebo
        RCLCPP_INFO(this->get_logger(),
            "Received velocity command: linear=%f, angular=%f",
            msg->linear.x, msg->angular.z);
    }

    rclcpp::Subscription<geometry_msgs::msg::Twist>::SharedPtr cmd_vel_sub_;
    rclcpp::Publisher<sensor_msgs::msg::LaserScan>::SharedPtr laser_pub_;

### 6.3.3 Unity ROS Bridge (ROS#)

ROS# enables communication between Unity and ROS 2:

```csharp
// Example Unity C# script for ROS communication
using UnityEngine;
using RosSharp.RosBridgeClient;
using RosSharp.Messages.Geometry;

public class UnityRobotController : MonoBehaviour
{
    private RosSocket rosSocket;
    private string robotName = "unity_robot";

    void Start()
    {
        // Connect to ROS bridge
        WebSocketNativeClient webSocket = new WebSocketNativeClient("ws://localhost:9090");
        rosSocket = new RosSocket(webSocket);

        // Subscribe to velocity commands
        rosSocket.Subscribe<Twist>("/cmd_vel", ReceiveVelocityCommand);
    }

    private void ReceiveVelocityCommand(Twist twist)
    {
        // Apply velocity to Unity robot
        Vector3 linear = new Vector3((float)twist.linear.x, (float)twist.linear.y, (float)twist.linear.z);
        Vector3 angular = new Vector3((float)twist.angular.x, (float)twist.angular.y, (float)twist.angular.z);

        // Move the robot in Unity
        transform.Translate(linear * Time.deltaTime);
        transform.Rotate(angular * Time.deltaTime);
    }

    void OnDestroy()
    {
        rosSocket.Close();
    }
}
```

### 6.3.4 Physics Configuration in Unity

Configuring Unity's physics engine for realistic robot simulation:

```csharp
// Physics configuration for robot components
using UnityEngine;

public class RobotPhysicsConfig : MonoBehaviour
{
    [Header("Joint Configuration")]
    public float jointSpring = 10000f;
    public float jointDamper = 100f;
    public float jointForceLimit = 1000f;

    [Header("Rigidbody Configuration")]
    public float robotMass = 50f;
    public float frictionCoefficient = 0.8f;
    public float bounciness = 0.1f;

    void Start()
    {
        ConfigureRigidbodies();
        ConfigureJoints();
    }

    private void ConfigureRigidbodies()
    {
        Rigidbody[] rigidbodies = GetComponentsInChildren<Rigidbody>();
        foreach (Rigidbody rb in rigidbodies)
        {
            rb.mass = robotMass / rigidbodies.Length;
            rb.drag = 0.1f;
            rb.angularDrag = 0.05f;
            rb.interpolation = RigidbodyInterpolation.Interpolate;
        }
    }

    private void ConfigureJoints()
    {
        ConfigurableJoint[] joints = GetComponentsInChildren<ConfigurableJoint>();
        foreach (ConfigurableJoint joint in joints)
        {
            JointSpring spring = joint.spring;
            spring.spring = jointSpring;
            spring.damper = jointDamper;
            spring.targetPosition = 0;
            joint.spring = spring;

            joint.linearLimit = new SoftJointLimit { limit = 45f };
            joint.angularXLimit = new SoftJointLimit { limit = 30f };
            joint.angularYLimit = new SoftJointLimit { limit = 45f };
            joint.angularZLimit = new SoftJointLimit { limit = 30f };
        }
    }
}
```

### 6.3.5 Sensor Simulation in Unity

Implementing realistic sensor simulation in Unity:

```csharp
// Camera sensor simulation
using UnityEngine;
using RosSharp.RosBridgeClient;
using RosSharp.Messages.Sensor;

public class UnityCameraSensor : MonoBehaviour
{
    public Camera sensorCamera;
    private Texture2D sensorTexture;
    private RosSocket rosSocket;
    private int imageWidth = 640;
    private int imageHeight = 480;

    void Start()
    {
        sensorTexture = new Texture2D(imageWidth, imageHeight, TextureFormat.RGB24, false);
        rosSocket = GameObject.Find("ROSConnector").GetComponent<UnityROSGeometryConnector>().rosSocket;
    }

    void Update()
    {
        if (Time.frameCount % 30 == 0) // Publish every 30 frames (approx 2 Hz)
        {
            RenderTexture currentRT = RenderTexture.active;
            RenderTexture.active = sensorCamera.targetTexture;

            sensorCamera.Render();
            sensorTexture.ReadPixels(new Rect(0, 0, imageWidth, imageHeight), 0, 0);
            sensorTexture.Apply();

            RenderTexture.active = currentRT;

            PublishImage();
        }
    }

    private void PublishImage()
    {
        byte[] imageBytes = sensorTexture.EncodeToPNG();
        Image rosImage = new Image
        {
            header = new Messages.Std.Header { stamp = new Time() },
            height = (uint)imageHeight,
            width = (uint)imageWidth,
            encoding = "rgb8",
            is_bigendian = 0,
            step = (uint)(imageWidth * 3),
            data = imageBytes
        };

        rosSocket.Publish("/camera/image_raw", rosImage);
    }
}
```

### 6.3.6 LIDAR Simulation in Unity

Creating realistic LIDAR simulation in Unity:

```csharp
// Raycast-based LIDAR simulation
using UnityEngine;
using System.Collections.Generic;
using RosSharp.RosBridgeClient;
using RosSharp.Messages.Sensor;

public class UnityLidarSensor : MonoBehaviour
{
    [Header("LIDAR Configuration")]
    public int horizontalRays = 360;
    public int verticalRays = 1;
    public float minAngle = -Mathf.PI;
    public float maxAngle = Mathf.PI;
    public float maxRange = 30f;
    public LayerMask detectionLayers;

    private RosSocket rosSocket;
    private float[] ranges;

    void Start()
    {
        ranges = new float[horizontalRays * verticalRays];
        rosSocket = GameObject.Find("ROSConnector").GetComponent<UnityROSGeometryConnector>().rosSocket;
    }

    void Update()
    {
        if (Time.time % 0.1f < Time.deltaTime) // Publish at 10 Hz
        {
            SimulateLidarScan();
        }
    }

    private void SimulateLidarScan()
    {
        for (int i = 0; i < horizontalRays; i++)
        {
            float angle = minAngle + (i * (maxAngle - minAngle)) / (horizontalRays - 1);

            Vector3 direction = new Vector3(Mathf.Cos(angle), 0, Mathf.Sin(angle));
            RaycastHit hit;

            if (Physics.Raycast(transform.position, direction, out hit, maxRange, detectionLayers))
            {
                ranges[i] = hit.distance;
            }
            else
            {
                ranges[i] = maxRange;
            }
        }

        PublishLidarScan();
    }

    private void PublishLidarScan()
    {
        LaserScan laserScan = new LaserScan
        {
            header = new Messages.Std.Header { stamp = new Time() },
            angle_min = minAngle,
            angle_max = maxAngle,
            angle_increment = (maxAngle - minAngle) / (horizontalRays - 1),
            time_increment = 0,
            scan_time = 0.1f,
            range_min = 0.1f,
            range_max = maxRange,
            ranges = ranges
        };

        rosSocket.Publish("/scan", laserScan);
    }
}
```

Digital twin environments like Gazebo and Unity provide essential capabilities for developing and testing humanoid robotics systems. Gazebo excels in physics accuracy and ROS integration, while Unity offers superior graphics and flexible environment creation. Understanding how to effectively use these tools enables safer, more efficient robotics development with reduced costs and risks.

The key to successful digital twin implementation lies in balancing simulation fidelity with performance requirements, properly modeling sensor noise and imperfections, and validating simulation results against real-world behavior. As robotics systems become more complex, digital twins will continue to play an increasingly important role in development, testing, and deployment.
